## Deliverables

### 1. New workflow `.github/workflows/security.yml`
Runs on push, pull_request and a weekly schedule. Each job sets least-privilege `permissions:`, and actions are pinned by full SHA with a `# vX.Y.Z` comment. Resolve SHAs with `git ls-remote`; never invent them.
- **gitleaks:** full history scan. The gitleaks-action needs a licence key for orgs but not for personal accounts; confirm this. If it can't run keyless, run the `zricethezav/gitleaks` container instead.
- **semgrep:** `semgrep scan --config p/python --config p/typescript --config p/owasp-top-ten --error`, using the official container.
- **SCA:**
  - `pip-audit` against `uv export --frozen --no-dev --format requirements-txt`, plus a second run including dev dependencies that doesn't block the build.
  - `osv-scanner` over both lockfiles.
- **zizmor:** GitHub Actions security lint over `.github/workflows/`. Fix what it reports, including evaluating `pull_request_target` in `pr-title.yml`.
- **Trivy config scan:** `trivy config .` covering Dockerfile and compose once they exist. Today it covers the workflows and repo config.
- **License compliance:**
  - Python: `pip-licenses` fails on GPL/AGPL. LGPL is allowed only where it is dynamically linked, and must be listed.
  - Web: `license-checker` or `pnpm licenses list` with the same policy.
  - Generate `THIRD_PARTY_NOTICES.md`, and note that FFmpeg (LGPL) is bundled inside PyAV wheels.
- **OpenSSF Scorecard:** a separate `scorecard.yml`. It needs a public repo for full results, so gate it to `github.event.repository.private == false`, keep it in the repo, and document that it activates at v1.0.

### 2. Carry-over fixes (required)

- **Node 20 actions.** Bump `actions/checkout`, `actions/setup-node`, `pnpm/action-setup` and `astral-sh/setup-uv` to majors that run on Node 24, SHA-pinned.

### 3. Local parity: `just security`
- Runs everything that works on this Windows machine through project-managed dependencies only: `pip-audit` and `zizmor` via `uv` dev deps or `uvx`, `pnpm audit`, the license checks, and the scorecard `--check`.
- Tools that need binaries or containers (semgrep, osv-scanner, trivy, gitleaks) are **CI-only**. `just security` prints a clear notice for each skipped tool. **Do not download binaries or install anything globally.** If you believe a binary is essential locally, write `BLOCKED: provision <tool>`.
- Don't add `just security` to `just check`; it needs network. Do add a `security` job to CI that runs it on Linux.

### 4. Triage
- Every finding is either **fixed** (with a test where it's code) or recorded as an **accepted risk** in `docs/security/accepted-risks.md` with an id, finding, tool, rationale and an **expiry date ≤ 90 days**.
- Add a `suppressions` mechanism that references the accepted-risk id, such as semgrep `nosemgrep: <rule> -- AR-001` or a pip-audit `--ignore-vuln` list sourced from that file. The scorecard validator must fail on any suppression without a matching, unexpired accepted risk. Add tests for this.

### 5. Re-score
Update `docs/security/samm/assessment.yaml` and `dsomm/activities.yaml` for the controls that now exist, with evidence pointing to the workflow files, then regenerate the scorecards and gaps. Only claim what is genuinely implemented; CI-only is fine as evidence.
