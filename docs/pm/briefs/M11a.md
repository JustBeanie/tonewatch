## Scope (this brief only)
1. **M11.1 Scaffold.**
   - **Integration files:** `custom_components/tonewatch/`:
     - `manifest.json`: `domain: tonewatch`, `name: ToneWatch`, `config_flow: true`, `iot_class: local_push`, `zeroconf: ["_tonewatch._tcp.local."]`, `integration_type: service`, and `codeowners: ["@JustBeanie"]`, `documentation` and `issue_tracker` URLs pointing at this repo, `version: 0.1.0`, `requirements: []` unless one is truly needed.
     - `__init__.py`, `const.py`, `strings.json`, `translations/en.json`
   - **Repo files:** `hacs.json`, `README.md` (with the "supplemental notification tool, not a certified primary alerting system" disclaimer), `.gitignore`, `pyproject.toml`.
   - **Tooling:** ruff (strict, as in tonewatch), mypy strict, pytest with `pytest-homeassistant-custom-component` pinned to a version compatible with a current HA release, and a `uv.lock`.
   - **Local gates:** a `justfile` with `lint`, `typecheck`, `test` and `check`.
2. **M11.2 Config flow.**
   - **User step:** host, port (default 8099) and API token. Validate by calling the ToneWatch API with the bearer token and map errors to `cannot_connect` / `invalid_auth`.
   - **Discovery steps:** `async_step_zeroconf`, and `async_step_hassio` for Supervisor discovery with a confirm step.
   - **Reauth:** `async_step_reauth` / `async_step_reauth_confirm`.
   - **Duplicates:** abort on an already-configured instance using ToneWatch's stable instance id. Find where the app exposes it; if it isn't exposed over the API or zeroconf TXT, report that as a tonewatch-side gap rather than inventing one.
   - **Never log the token.**
3. **M11.3 `api.py`.**
   - **Connection:** a WebSocket client on HA's aiohttp session (`async_get_clientsession`) against `/api/ws`, with bearer auth exactly as the tonewatch server expects.
   - **Reconnect:** exponential backoff with jitter and a bounded maximum.
   - **Coordinator:** a `DataUpdateCoordinator` fed by push, not polling. Handle the domain event types from `ws_models.py`, and handle unload and cancellation cleanly.
   - **No entities yet.** They are M11.4, a later brief. Store the latest state in the coordinator so M11.4 can build on it.
4. **M11.8 CI baseline.**
   - **Workflow:** `.github/workflows/ci.yml` running hassfest, `hacs/action`, ruff, mypy and pytest. Pin every action to a full commit SHA with a version comment, set least-privilege `permissions`, `timeout-minutes` on every job, and `persist-credentials: false`.
   - **Dependency updates:** add `.github/dependabot.yml` for GitHub Actions and pip (or uv).
   - **Pin verification:** you are offline, so write the pinned SHAs you intend. The PM verifies them before pushing. List each pin with its tag in your report.
