## legacy tones.cfg `tones.cfg` format (PM-verified against the vendor sample and the user's real file)
- **Structure:**
  - INI-style `[Section]` headers, one per page definition. Section names are arbitrary labels like `[PageA]` and `[Longtone1]`; the **keys** decide the type, not the name.
  - `key = value` lines. Keys are **case-insensitive** (`Atone` and `atone` both appear). Values and keys may carry trailing spaces or **tabs**.
  - Blank values (`gaplength = `) mean "unset".
  - A `__name__` key may appear and is ignored.
  - Treat a UTF-8 BOM and CRLF line endings as normal.
- **Two-tone section:** `atone`, `btone` (Hz, decimal) and `atonelength`, `btonelength` (seconds; `.6` without a leading zero occurs).
- **Long-tone section:** `longtone` (Hz) and `longtonelength` (seconds).
- **Common keys:**
  - `description`: the human name
  - `tone_tolerance`: a **fraction**, e.g. `0.02` means ±2 %
  - `record_delay` (s), `record_seconds` (s), `release_time` (s), `ignore_after` (s)
  - `gaplength` (s)
  - `playback_during_record` (0/1)
  - `exclude_from`, `exclude_to`: a time window
  - `text_emails`, `mp3_emails`, `amr_emails`: comma-separated, may use `"Name"<addr>` display-name syntax
  - `email_subject`, `email_body`: with `[d]`/`[t]` placeholders
  - `post_email_command`, `alert_command`: shell commands
  - `iar_tone_id`
  - Other keys may exist; treat them as unknown.

## Mapping (legacy tones.cfg → `ToneSet`)
| legacy tones.cfg | ToneWatch | Rule |
|---|---|---|
| `atone`/`atonelength`, `btone`/`btonelength` | `sequence` = two `ToneSpec(freq_hz, min_s)` | Both tones required for a two-tone section |
| `longtone`/`longtonelength` | `sequence` = one `ToneSpec` | |
| `tone_tolerance` | `tol_pct = fraction × 100` on every tone | Missing → model default + a note. Outside the model range (0.1–10) → that section fails with a clear error. |
| `description` | `name` | Missing → section name |
| slug of `description` | `id` | Deduplicate with `-2`, `-3`; also against existing tone-set ids when merging |
| `record_seconds` | `record.post_s` | Missing → model default |
| `ignore_after` | `cooldown_s` | Missing → model default |
| `gaplength` | `max_gap_s` | Only if set and positive |
| everything else | **not imported** | Reported per section as notes **by key name only** |

- **Never auto-create alert targets from legacy tones.cfg commands.** `post_email_command` and `alert_command` are shell strings. Report them as "not imported: configure a script alert target manually". Never turn them into `ScriptTarget`s: an untrusted file must not become code execution.
- **Never echo email addresses anywhere:** not in reports, logs, API responses or exceptions. Report counts only, e.g. "2 email recipient fields not imported (use a webhook or MQTT target)".
- Each section maps independently. A bad section produces a per-section error and the rest still import. The result says `n imported, m skipped` with reasons.

## Required
1. **`backend/src/tonewatch/importers/tones_cfg.py`**, a pure function API:
   - `parse_tones_cfg(text: str) -> TonesCfgImportResult` holds the proposed `ToneSet`s plus per-section notes and errors.
   - `apply_import(config: AppConfig, result, mode: Literal["merge","replace"]) -> AppConfig`.
     - `merge` appends with id deduplication.
     - `replace` swaps **only** `tone_sets`, never sources or alert targets.
   - No file I/O inside the parser, and typed errors.
   - **Limits:** at most 256 KiB of text and at most 500 sections, matching `AppConfig.tone_sets` `max_length`.
2. **CLI:** `tonewatch import tones-cfg <path> [--apply] [--mode merge|replace] [--json]`.
   - **Dry run by default:** it prints the preview table (or JSON) and exits 0 with nothing written.
   - `--apply` writes through `ConfigStore` (atomic write + backup) and hot-reload isn't required.
   - Exit code non-zero when every section failed.
3. **API:** `POST /api/import/tones-cfg` accepts a multipart upload or a raw text body.
   - **Auth:** requires auth + CSRF like other state-changing routes, enforces the 256 KiB limit with 413, and records an audit entry with counts only.
   - `?apply=false` (default) returns the preview. `apply=true` + `mode` persists and hot-applies through the same path as tone-set CRUD.
   - Regenerate the OpenAPI client (`just gen-api`).
4. **Web (M6.4 import):** an "Import from the legacy notifier" action on the tone-sets page.
   - **Flow:** file picker → preview table (name, tones, tolerance, notes/errors per row) → Merge or Replace confirm → apply → list refresh.
   - **Accessibility:** jsx-a11y clean.
   - **Vitest:** preview rendering, error rows, and that the Replace confirm is required.
5. **Tests:**
   - **Committed synthetic fixtures** under `backend/tests/fixtures/tones_cfg/`, written by you with invented names and frequencies. Don't copy the vendor sample or the user's file. Cover:
     - mixed-case keys, trailing tabs, blank values, `__name__`, BOM, CRLF, `.6` lengths
     - a long-tone section and a two-tone section
     - tolerance missing, in range and out of range
     - duplicate descriptions
     - email display-name syntax, which must not leak into any output
     - command keys, which must be reported and not imported
     - a malformed section among good ones
   - **Hypothesis:** the parser never raises anything but its typed error on arbitrary text, and never exceeds limits.
   - **Detection proof:** for each two-tone and long-tone synthetic section, synthesize audio with `dsp/generator.py` at the imported frequencies and lengths, run the detector (`analyze` path), and assert the imported tone set detects it. The importer's output must actually work, not just validate.
   - **Private real-world test:**
     - It reads `backend/tests/fixtures/private/tones_cfg/tones.cfg` (already placed in your worktree by the PM; gitignored), with `pytest.skip` when absent.
     - Assert **structural** properties only: at least one tone set imported, zero section errors, all frequencies within model bounds, every tolerance equal to 2.0 %, and no `@` anywhere in the CLI JSON output or the API response.
     - **Never hardcode names, frequencies or addresses from that file** in committed code, and never print its contents.
   - **API tests:** auth required, CSRF required for cookie sessions, 413 over the limit, preview has no side effects, `apply` persists, and `replace` leaves sources and targets intact.
6. **Security docs:**
