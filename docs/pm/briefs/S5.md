## Required
1. **DAST in CI**: a new job `dast` in `.github/workflows/docker.yml` (`needs: build-amd64`).
   - **Target:** run the hardened container exactly as `e2e-container` does. Reuse `scripts/e2e_fixture.py`, a read-only root, `cap_drop ALL` and `no-new-privileges`.
   - **Baseline scan:** ZAP baseline against `http://127.0.0.1:8099/`.
   - **API scan:** ZAP API scan against the served `openapi.json`. Export it from the running container (`/api/openapi.json`, or whatever the app serves; check `api/app.py`), or use the committed `web/src/api/openapi.json`.
   - **Authentication:** API endpoints need the bearer token. Read it from the container (`docker exec … cat /data/api_token`) and pass it with ZAP's replacer/auth header configuration, so the scan exercises authenticated routes, not just 401s.
   - **Pinning:** use the official ZAP container image **pinned by digest**, and verify that the digest exists. The PM checks every digest against the registry.
   - **Rules file:** `docker/zap/rules.tsv`. The default is FAIL on Medium and High. Every `IGNORE` or `WARN` override needs a one-line justification tied to this app, for example "CSP report-only not used; CSP is enforced", and **no blanket ignores**.
   - **Artifacts:** upload the HTML and JSON reports with `if: always()`. `timeout-minutes` and per-job `permissions: {contents: read}` are required.
   - **Real findings:** if ZAP finds a real issue, fix it in the app with a regression test. Don't suppress it.
2. **Container hardening proof.**
   - **Hardening test:** add `test_compose_files_are_hardened`, a Python unit test that parses the three compose files. Every service must have `read_only: true`, `cap_drop: [ALL]`, `security_opt` containing `no-new-privileges:true`, a tmpfs at `/tmp`, a healthcheck, and a published `8099`. This makes the M8 hardening a regression-tested contract.
   - **Trivy config:** extend the existing `trivy config` scan to include `docker/`, and confirm it's clean.
   - **HIL checklist:** create `docs/hil-checklist.md`, the hardware-in-the-loop checklist the PLAN references. Cover sound card and RTL-SDR device mappings under these hardening flags, the HA add-on, the Windows build, stream reconnect and the feed-health sensor. Give each item exact steps, expected results and a `[ ]` result line. **Don't claim hardware results;** the user runs this.
3. **ASVS evidence integrity** (from carryover).
   - **Evidence snippets:** add an `evidence snippet` column to `docs/security/asvs/checklist.csv`: the exact code substring that proves the row.
     - `test_asvs_checklist.py` must locate the snippet in the cited file, failing if it's absent or appears more than once, and derive the line from it.
     - `path:line` must equal the located line, or be replaced by `path` alone plus the snippet.
     - Keep the snippet approach resilient to line shifts. That fragility is the whole reason for this item.
   - **Vendored sha test:** `test_vendored_asvs_csv_matches_pinned_sha256` hashes `docs/security/asvs/source/OWASP_Application_Security_Verification_Standard_5.0.0_en.csv` and compares it to the pin in that directory's `README.md`.
   - **S4-close nits:**
     - V3.3.2 (SameSite) must cite the `set_cookie` samesite argument, with a test asserting the SameSite attribute.
     - V16.5.1's note must drop its "applicability justified" phrase unless the validator still needs it; explain which.
   - **Gap conversion limited to V3 and V4:** use the new DAST job and existing tests as evidence where they **directly** prove a requirement. The gap-by-default rule still applies. Every converted row cites a specific control and test, and the PM reviews every converted row. Don't touch other chapters.
4. **Action-pin hygiene across ALL workflows** (from carryover).
   - **Re-pin:** every action in `.github/workflows/*.yml` gets a **commit** SHA with an exact `# vX.Y.Z` comment. `ci.yml` currently pins `pnpm/action-setup@a8198c4…`, which is the annotated tag object; the commit is `fc06bc1257f339d1d5d8b3a19a8cae5388b55320`.    - **Checker:** run `scripts/check_action_pins.py` over `.github/workflows/*.yml` in both `just security` and `security.yml`. Keep its unit tests passing, and extend them if you change behaviour.
