## Priority fixes (do these first; each needs named tests)
1. **TM-027: stream URL SSRF and FFmpeg protocol abuse.**
   - `StreamSource` URLs go to PyAV/FFmpeg, which honours `file:`, `concat:`, `subfile:`, `data:`, `pipe:`, `crypto:` and more.
   - **Fix:**
     - a scheme allowlist (`http`, `https`, `rtsp`, `rtsps`), validated on config save (422) **and** at open time
     - pass FFmpeg `protocol_whitelist` restricted to `http,https,tcp,tls,rtsp,rtp,udp` for the scheme in use
     - resolve and check the host with `alerts/urlsafety.py`: block loopback, link-local, metadata and encoded forms; **allow** RFC1918 LAN by default, with `settings.stream_block_private`
     - disable or limit redirects (FFmpeg `http` option) and re-validate them
   - **Tests:**
     - `test_stream_rejects_file_concat_data_pipe_schemes` (API 422 and `open()`)
     - `test_stream_protocol_whitelist_passed_to_pyav` (spy on `av.open` options)
     - `test_stream_blocks_metadata_and_loopback_allows_lan`
     - `test_stream_redirect_to_blocked_host_refused`
     - **Proof of exploit, first:** a test showing that before the fix `file:` could read `api_token`, then the fix. Keep the test as a regression.
2. **Secrets in rendered logs** (carry-over from M5a; TM-011 partial). `test_secrets_never_logged` uses `capture_logs`, which bypasses processors. Add `test_rendered_log_output_redacts_secrets`: configure real logging, drive login, bearer, cookie and webhook-secret flows, capture the **rendered JSON** from the handler, and assert the redaction markers are present and the secrets absent.
3. **Chunked upload guard** (carry-over): `test_analyze_chunked_body_rejected_after_limit_without_reading_rest`, counting `receive()` pulls in a custom ASGI harness.
4. **S3 partial/open threats assigned to S4:**
   - **TM-002, token file protection:** POSIX `0600` enforced and verified on startup, warning or refusing when too open. On Windows, apply an owner-only ACL via `icacls`-equivalent Win32 calls, **or** document it as an accepted risk with an expiry. Test the POSIX path; skip that test on Windows with a reason.
   - **TM-005, config write race:** a process-wide `asyncio.Lock` plus an inter-process file lock around read-modify-write in `ConfigStore`, with optimistic concurrency: an `etag`/revision on `GET` and `If-Match` on writes, returning 412 on mismatch. Test that concurrent writers don't lose updates.
   - **TM-009 / TM-010, audit log:** an append-only audit trail (DB table + migration) for config changes (actor = session / bearer / ingress, with before/after **diff with secrets masked**), test-page triggers, token rotation and login success/failure. Add `GET /api/audit` (authenticated, paginated). Test each event type.
   - **TM-018, slow-loris:** set uvicorn `timeout_keep_alive`, `h11_max_incomplete_event_size` and `limit_concurrency` in `tonewatch serve`, and document the settings. Test that the settings are applied (config object).
   - **TM-021, resource exhaustion:** caps on tone sets (for example 500), sources (for example 16) and sequence length, enforced in `AppConfig` validation. Test that 422 is returned.
   - **TM-022, throttle memory:** a bounded LRU for login-throttle state with eviction, where memory stays flat under many spoofed IPs. Test it.
   - **TM-007, decoder exposure:** run PyAV decode for **uploads** (`/api/analyze`) with duration and size caps already in place; add a decode timeout and reject files whose header claims more than 10 minutes before decoding. Stream decoding stays in-process, accepted with a rationale. Test the timeout.

## The audit itself
- **`docs/security/asvs/checklist.csv`:** one row per **L1 + L2** requirement in the pinned source. Columns: `id, chapter, requirement (verbatim), level, applicable (yes/no), status (pass/fail/fixed/na/accepted), evidence (path:line), test (function name), notes`.
  - N/A rows need a concrete reason, for example "no OAuth/OIDC in scope", "no payment functionality" or "no user self-registration".
  - `accepted` rows must reference an `AR-###` entry with an expiry of 90 days or less.
- **`backend/tests/unit/test_asvs_checklist.py`:**
  - every pinned L1/L2 requirement id appears exactly once
  - `pass`/`fixed` rows cite an existing path:line **and** an existing test function
  - `accepted` rows reference an unexpired accepted risk
  - `fail` count = 0
- **Chapters to scrutinise hardest:** V1 Encoding/Sanitization, V2 Validation, V3 Web Frontend Security (headers, CSP for the SPA served by the backend), V4 API and Web Service, V5 File Handling, V6 Authentication, V7 Session Management, V8 Authorization, V9 Self-contained Tokens (likely N/A), V11 Cryptography (scrypt parameters, token entropy, HMAC), V12 Secure Communication (TLS is a deployment concern: document it), V13 Configuration (secrets, debug off), V14 Data Protection (recordings are sensitive radio traffic: retention, access control), V16 Security Logging.
- **Threat model sync:** update `docs/security/threat-model/README.md` statuses to `mitigated` where fixed, citing path:line and test, and update `gaps.md`. The `test_threat_model.py` tests must pass.
- **SAMM re-score:** Requirements-driven Testing (A: Control Verification, B: Misuse/Abuse Testing), Security Testing, Defect Management. Regenerate the scorecards.

## Rules
- Reproduce before fixing: for each real vulnerability, the regression test must fail against the pre-fix code (state that you verified this).
- No `pragma: no cover`, `noqa` or `type: ignore` without a same-line justification. The PM greps for all three.
- Don't weaken existing security tests.
