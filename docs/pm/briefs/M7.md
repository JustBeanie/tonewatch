## Required design
- **Shared `alerts/urlsafety.py`,** used by webhooks now and by the stream-SSRF fix in S4:
  - The scheme allowlist is set per caller; for webhooks, `https` plus `http` only when `allow_insecure_http` is set.
  - Resolve DNS **once** and connect to the resolved IP, which defeats DNS rebinding: use an `httpx` transport or connection hook that pins the IP and keeps the `Host` header and SNI.
  - Block loopback, link-local (including `169.254.169.254` and `fe80::/10`), unspecified, multicast, IPv4-mapped IPv6 forms of those, and the `0.0.0.0/8` and `::` addresses.
  - RFC1918 and ULA private ranges are **allowed by default**, because LAN Home Assistant webhooks are the main use case. `settings.webhook_block_private` blocks them.
  - **Redirects are not followed** by default. If enabled, every hop is re-validated.
  - Pure functions with exhaustive parametrized tests, including decimal/octal/hex IP encodings (`http://2130706433/`, `http://0x7f.1/`) and `[::ffff:127.0.0.1]`.
- **M7.1 `alerts/dispatcher.py`.**
  - Subscribes to `ToneDetected` (pre-alert), `RecordingReady` and `CallClosed`, and maps tone set `alert_targets` to target instances.
  - **Dedupe:** keyed by `(call_id, target_id, phase)`; a stacked page must not re-alert a target already alerted for that call and phase.
  - **Retry:** exponential backoff (1 s, 2 s, 4 s, 8 s, 16 s; max 5 attempts; jitter) with an injected sleep.
  - Write an `AlertAttempt` row per attempt (ok, status, error truncated to 500 chars, **no secrets**).
  - Targets run concurrently with a per-target timeout. One slow or failing target never delays the others.
  - `test=true` events (from `POST /api/tonesets/{id}/test`) are delivered, and marked as test in every payload.
  - Supervisor wiring: start and stop under the supervisor, and reload targets on config change.
- **M7.2 `alerts/mqtt.py`** (`aiomqtt`).
  - Connection settings from the target: host, port, TLS, username and password. **In add-on mode, credentials come from the Supervisor `/services/mqtt` endpoint** when none are configured; mock it in tests.
  - LWT on `tonewatch/<instance_id>/availability` (`online`/`offline`, retained).
  - Publish `tonewatch/<instance_id>/call` (JSON: call_id, tone sets, phase, detected_at, recording_url when known, test flag) and `tonewatch/<instance_id>/health/<source_id>`.
  - Reconnect with backoff, and keep a bounded outbox while disconnected.
- **M7.3 `alerts/ha_discovery.py`.**
  - Publish retained discovery under `homeassistant/`:
    - a device per instance
    - `event` entities per tone set (`event_types: [pre_alert, recording_ready]`)
    - `sensor.last_call`
    - `binary_sensor.call_active`
    - `binary_sensor.<source>_feed_healthy`
  - Unique ids are stable, derived from `instance_id` plus the entity key. Entities follow the availability topic.
  - **When a tone set or source is deleted**, publish an empty retained payload to clear its discovery topic.
  - Default off when HA integration mode is configured (flag in settings).
- **M7.4 `alerts/webhook.py`.**
  - JSON POST, validated through `urlsafety`.
  - **HMAC-SHA256** signature over `timestamp + "." + body`, sent in `X-ToneWatch-Timestamp` and `X-ToneWatch-Signature: sha256=<hex>`, with a per-target secret. Document how receivers should verify it (constant-time compare, 5-minute replay window).
  - Timeout of 10 s. The response body is read up to 64 KB only.
  - Optional multipart audio attachment (`include_audio`), with a size cap from settings (default 10 MB). The file is read from `recordings_root` through the same path check as the recordings route.
  - The secret is never logged, and never included in `AlertAttempt.error`.
- **M7.5 `alerts/script.py`.**
  - Disabled unless **both** `settings.allow_script_targets` is true **and** the target is enabled. Keep the API 403 guard.
  - `executable` must be an absolute path inside `settings.script_allowlist_dirs` (default empty, which means nothing is allowed). Resolve symlinks, and refuse world-writable files on POSIX.
  - The args template allows only the placeholders `{call_id}`, `{toneset}`, `{recording_path}`, `{source_id}` and `{phase}`. **Each placeholder expands into a single argv element**; values can never split or inject arguments. Any other brace is an error when the config is saved.
  - Run with `asyncio.create_subprocess_exec`, **no shell**, and a minimal environment: only `PATH=/usr/bin:/bin` plus `TONEWATCH_*` variables, **never** the API token or `SUPERVISOR_TOKEN`. cwd is a temp dir.
  - Timeout of 30 s by default; on timeout, kill the process and reap it with `communicate()` (see the rtlsdr fix for why).
  - stdout and stderr are captured and truncated to 4 KB into the attempt record.
