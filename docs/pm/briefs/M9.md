## Goal
Ship ToneWatch as a native Windows onedir build: the web UI, PortAudio (WASAPI) and PyAV bundled, and running as a Windows service. Docker Desktop can't pass sound cards or USB SDRs into a Linux container, so Windows users need this build.

## Environment facts (verified by PM)
- This machine is Windows 11, so you **can** run PyInstaller locally. Build the onedir yourself and run the smoke commands against `dist/`.
- The Codex sandbox has **no network TLS** (schannel has no credentials), so HTTPS probes, `git ls-remote` and `curl` fail inside it. Don't draw TLS conclusions locally; mark them `PENDING-CI`.
- Installing a real Windows service needs admin rights, which the sandbox doesn't have. Real install, start and uninstall happens **only** in `windows.yml` on `windows-latest`, where the runner is admin. Unit tests use a fake service manager.
- The action pin checker can't reach GitHub from the sandbox, so it skips. Resolve new action SHAs from pins already in the repo where possible. **Never downgrade** an existing pin, and list any new pins so the PM can verify them.

Every claim cites a test or a CI job step. There are no suppressions without a same-line justification. Don't split strings or restructure code to dodge a lint rule.

## Required
1. **M9.1 `packaging/windows/tonewatch.spec`**, a PyInstaller **onedir** build:
   - **Bundle:**
     - `tonewatch/web_dist`, built by `pnpm build` and copied in exactly as the Dockerfile does
     - the PortAudio DLL shipped inside the `sounddevice` wheel (`_sounddevice_data`)
     - PyAV's bundled FFmpeg DLLs
     - `certifi`'s CA bundle
     - Alembic migrations
     - SQLAlchemy/aiosqlite dialect hidden imports
   - **Import walk:** a smoke step imports every `tonewatch.*` module inside the frozen app, via a hidden `tonewatch selftest imports` subcommand or equivalent, so missing hidden imports fail in CI and not at a user's first call.
   - **Frozen data dir:** when frozen (`sys.frozen`) and `TONEWATCH_DATA_DIR` is unset, the data dir defaults to `%PROGRAMDATA%\tonewatch`. Unfrozen behaviour stays exactly as it is.
     - Unit-test both branches with monkeypatched `sys.frozen` and environment.
     - Never write to `C:\ProgramData` in tests; use `tmp_path`.
   - **PyInstaller is a dev/packaging dependency only.** `uv export --no-dev` for Linux must not change, so the Docker image size (a 2.8 MB margin) is unaffected. Prove it with a test or a CI step that diffs the Linux runtime export.
   - Add a `just windows-build` recipe that fails clearly on non-Windows hosts.
2. **M9.2 `tonewatch service install|uninstall|start|stop|status`**:
   - **Mechanism:** use a **pywin32** service wrapper, declared as a `sys_platform == 'win32'` marker dependency so Linux installs and the image never get it. Record the choice in `docs/decisions/0008-windows-service.md`: NSSM needs a separately downloaded third-party binary with its own update and licensing burden.
   - **Service config:**
     - service name `ToneWatch`
     - automatic (delayed) start
     - runs `tonewatch serve` with the frozen data dir
     - recovery actions: restart on failure
   - **Stop behaviour:** the service must stop gracefully by triggering the same shutdown path as Ctrl+C / lifespan shutdown (supervisor finalize, recordings flushed; see ADR 0006). It must not kill the process.
   - **Unit tests** through an injected fake service-manager seam:
     - install arguments
     - uninstall of a missing service gives a clear error with a non-zero exit
     - the stop request reaches the app's shutdown event
     - on non-Windows, the `service` subcommand exits non-zero with a clear message
   - **Licensing:** pywin32 is PSF-licensed. Add it to `THIRD_PARTY_NOTICES.md` and make sure `scripts/license_check.py` passes **without** widening its policy.
3. **M9.3 `.github/workflows/windows.yml`**, on PR and push to `main`, `windows-latest`, `timeout-minutes`, `permissions: {contents: read}`, and actions pinned by commit SHA with exact `# vX.Y.Z` comments (reuse the repo's existing pins):
   - **Build:** web build, uv sync, PyInstaller onedir, then zip `dist/tonewatch` and upload it as an artifact.
   - **Smoke against the built exe, not `uv run`:**
     - `--version`
     - `devices`: must exit 0 on a runner with no audio devices and print an empty or valid list
     - `analyze` on a generated fixture WAV (reuse `scripts/e2e_fixture.py`), asserting the expected detected call in JSON output
     - the frozen import walk
   - **Service lifecycle on the runner:**
     1. `tonewatch service install` with `TONEWATCH_DATA_DIR` pointed at a runner temp dir holding a file-source config
     2. `service start`, then poll `http://127.0.0.1:8099/readyz` (bounded loop, like docker.yml)
     3. `service stop`, then assert the process exited cleanly and the SQLite DB is not left locked
     4. `service uninstall`, then assert the service no longer exists
     5. dump the service log and data-dir logs on failure
   - **HTTPS:** from the frozen exe, open a public HTTPS URL through PyAV with the product options. On Windows, PyAV's FFmpeg uses **schannel, which ignores `ca_file`** and uses the OS store (carry-over). Assert that TLS verification happens, e.g. an `InvalidDataError` after a successful handshake as in docker.yml's smoke. Document the schannel behaviour in `docs/decisions/0008-windows-service.md` or `docs/windows.md`.
4. **Docs:** `docs/windows.md` covers:
   - install from the zip
   - the data dir location
   - service commands
   - firewall and bind host notes (default binds `127.0.0.1` unless configured)
   - token show/rotate
   - the schannel `ca_file` note
   - uninstall

   Update `README.md`'s install section with a link.

## Carry-over items that now belong to M9 (from `docs/pm/carryover.md`)
- **MQTT selector thread:** `test_mqtt_real_broker_via_selector_thread` in `backend/tests/integration/test_mqtt_broker.py` has an **unconditional `@pytest.mark.skip`**, so it runs on no platform. Make it a real broker round-trip on `windows-latest` (amqtt in its own `SelectorEventLoop` thread, or a pinned mosquitto binary; your choice, justified in the test docstring). Then remove the unconditional skip. Its `skipif(sys.platform != "win32")` stays. It must pass in `ci.yml / test-python (windows-latest)`, bounded by the 120 s pytest timeout.
- **sounddevice / NumPy 2.5:** sounddevice 0.5.6 sets `ndarray.shape` in its cffi callback, which NumPy 2.5 deprecates, and pytest runs `-W error`. Add a hermetic unit test that drives the soundcard source's callback conversion with a **fake** stream (never a real device), so a future NumPy removal fails CI instead of a user's soundcard. If the deprecation is inside sounddevice itself and unreachable without a device, document that in `docs/windows.md` under "known issues" and leave the HIL checklist item. Never add a warnings filter that hides it.
