## Requirements the PM will review against

### M1.1 Models (`config/models.py`)
- Use pydantic v2 with `model_config = ConfigDict(extra="forbid", frozen=True)` unless mutability is justified.
- `ToneSpec`:
  - `freq_hz` (250–3000)
  - `tol_pct` (0.1–10, default 1.5)
  - `min_s` > 0
  - `max_s` ≥ `min_s`, or `None` for unbounded
- `ToneSet`:
  - `id` (slug)
  - `name`
  - `sequence` (1–8 `ToneSpec`)
  - `max_gap_s` = 0.5
  - `cooldown_s` = 60
  - `enabled` = true
  - `alert_targets: list[str]` (target ids)
  - `record: RecordingPolicy`
- `RecordingPolicy`:
  - `pre_roll_s` (0–10, default 2)
  - `post_s` (default 60)
  - `silence_stop_s` (default 8)
  - `max_s` (default 300)
  - `formats` (`["mp3"]`, optional `"opus"`)
- `Source` is a discriminated union on `type`:
  - `soundcard`: device name or index, channel `left|right|mix`
  - `stream`: url
  - `rtlsdr`: freq_hz, gain, ppm, squelch
  - `file`: path, realtime bool, loop bool
  - Every variant carries `id`, `name`, `enabled` and `tonesets: list[str] | "all"`.
- `AlertTarget` is a discriminated union:
  - `mqtt`
  - `webhook`: url, secret, include_audio
  - `script`: executable, args template, timeout_s, enabled default **false**
- `AppConfig` validates **cross-references**: tone set `alert_targets` and source `tonesets` must reference existing ids, and ids are unique per kind. Errors must name the offending id.
- Adjacent tones in a sequence that fall within each other's tolerance are **allowed**, but produce a warning list returned by `AppConfig.lint()`. They are not a validation error.

### M1.2 Store (`config/store.py`, `settings.py`)
- `Settings` (pydantic-settings, prefix `TONEWATCH_`) holds data_dir, log level, bind host/port, and `addon_mode`, which is auto-detected from the `SUPERVISOR_TOKEN` env var.
- `ConfigStore.load()` / `.save(cfg)`:
  - YAML with ruamel or PyYAML `safe_load` only.
  - Writes are atomic: write a temp file in the same dir, `fsync`, then `os.replace`.
  - On first run, write a default config.
  - Keep a `.bak` of the previous file.
- **Add-on mode:** bootstrap settings are read from `/data/options.json`; the path is injectable for tests. The YAML config still lives in the data dir.
- Tests cover: round-trip, atomic write survives a simulated crash (monkeypatch `os.replace` to raise; the original stays intact), invalid YAML gives a clear error, env overrides, and add-on detection.

### M1.3 Storage (`storage/`)
- Async SQLAlchemy 2 on `aiosqlite`, with WAL mode enabled on connect.
- Tables:
  - `Call`: id uuid, started_at (tz-aware UTC), source_id, status `active|recorded|failed`
  - `CallToneSet`: call_id, toneset_id, detected_at, matched segment freqs as JSON
  - `Recording`: call_id, format, path, duration_s, size_bytes
  - `AlertAttempt`: call_id, target_id, attempt_no, ok, status/code, error, created_at
- Alembic lives in `storage/migrations`, with an initial migration that is **generated then reviewed**. Add a test that `alembic upgrade head` on an empty DB matches the ORM metadata (no autogenerate diff).
- Add a repository module with typed async functions; no ORM objects leak past it. Return frozen dataclasses or pydantic models.

### M1.4 EventBus (`events.py`)
- Domain events are frozen dataclasses: `ToneDetected`, `RecordingReady`, `FeedHealthChanged`, `CallClosed`, and `ConfigChanged`.
- `EventBus.subscribe(type | None) -> AsyncIterator`, with per-subscriber bounded queues (default 1000).
- A slow subscriber drops its **oldest** events and increments a `dropped` counter on that subscriber. It never blocks publish or other subscribers. Tests prove this.
- `publish` is sync-safe from a non-async thread via `loop.call_soon_threadsafe`, because the sounddevice callback runs in a thread.

## Lessons from M0 (PM-enforced)
- Use the `.tools/bin` PATH prefix from `AGENTS.md` for every command. No global installs.
- **Verification is only real if it ran.** Paste the unfiltered tails of `just check` and `uv run --project backend pre-commit run --all-files` in your final message.
  - pre-commit only sees tracked files, so stage new files first with `git add -A`. Staging is allowed; committing is not.
  - A hook that should have matched but printed `(no files to check)` is a failure.
- Don't pin exact patch interpreters (`--python 3.13.13`). CI runs on Linux.
- New dependencies go through `uv add --project backend <pkg>`, so the lockfile updates. Justify each one in your final message.
- `pytest` runs with `-W error`. Fix warnings; don't filter them, unless they come from a third-party package, in which case use a narrowly scoped `filterwarnings` entry with a comment.
