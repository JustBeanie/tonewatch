## Finding (blocking): oversized streamed body can silently apply a truncated import
When a streamed body without `Content-Length` crosses the limit, `limited_receive` sends 413. It then returns `{"type": "http.request", "body": b"", "more_body": False}`, which is a **fake clean end-of-body**. The app keeps running with only the bytes received before the limit.

Scenario:
1. `POST /api/import/tones-cfg?apply=true&mode=replace` is sent with a raw `text/plain` body of about 300 KiB, streamed in chunks without `Content-Length`.
2. `request.body()` returns the first ≤256 KiB, which ends at a section boundary or simply cuts off.
3. `parse_tones_cfg` succeeds on that truncated text.
4. `apply_import` in replace mode runs, and `save_config` persists the result and reloads the supervisor.
5. The client sees 413, but the tone sets were replaced by a partial import.

The route's `len(raw) > TONES_CFG_MAX_BYTES` check never sees the dropped bytes.

## Required
1. After the limit is crossed, the downstream app must **never** see a successful end-of-body.
   - For example, return `{"type": "http.disconnect"}` so Starlette raises `ClientDisconnect`, or raise a dedicated exception that the middleware catches.
   - Keep the 413 sent exactly once.
   - Make sure no later `send` from the app, or a 500 from an unhandled `ClientDisconnect`, leaks or double-starts a response.
2. Add a regression test that proves nothing was written:
   - Stream an oversized raw body without `Content-Length` to `apply=true&mode=replace`. Build the body from a valid synthetic config repeated past the limit, so a truncated prefix *would* parse.
   - Assert 413.
   - Assert the config (app state and saved YAML) is unchanged.
   - Assert no `tones_cfg_import` audit row exists.
   - Add the same test for multipart.
3. Also handle trailing-slash and root-path variants: confirm `/api/import/tones-cfg/` cannot reach the route without passing through the guard, or match on the resolved route instead of the raw path. Add a test for whichever holds.
