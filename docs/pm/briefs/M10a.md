## Required
1. **Add-on option keys.** These names are fixed; M10b's manifest `options`/`schema` will match them exactly.
   - **The keys:**
     - `log_level`: `debug|info|warning|error`
     - `public_base_url`: optional string
     - `mqtt_mode`: `supervisor|manual|off`, default `supervisor`
     - `ui_password`: optional; the Supervisor schema type is `password?`
   - **`Settings.load` behaviour:**
     - map these keys explicitly
     - warn in a structured log (keys only, never values) and ignore unknown keys
     - reject invalid values with a clear startup error naming the key
   - **Tests:** every key, an unknown key, an invalid value, and a password value never appearing in logs or `repr(settings)`.
2. **Supervisor MQTT credentials (M10.2).**
   - **Fetch:** in add-on mode with `mqtt_mode: supervisor`, fetch `GET http://supervisor/services/mqtt` with `Authorization: Bearer $SUPERVISOR_TOKEN`. The response `data` holds `host`, `port`, `ssl`, `username`, `password` and `protocol`.
   - **`MqttTarget`:** add `source: Literal["manual", "supervisor"] = "manual"`.
     - A `supervisor` target resolves broker host, port, TLS and credentials **at connect time** and re-fetches on every reconnect, because Supervisor rotates them.
     - Resolved credentials are **never** written to `config.yaml`, the audit trail, logs, API responses or HA discovery payloads.
   - **Config lint:** a `source: supervisor` target outside add-on mode is a validation warning (not a crash). The target reports unhealthy with a clear reason.
   - **First boot:** in add-on mode with `mqtt_mode: supervisor` and **no** MQTT targets in `config.yaml`, create one `source: supervisor` target named `Home Assistant MQTT` with HA discovery enabled. Persist it through the normal config store (atomic write + backup) so the user sees and can edit it in the UI.
     - `mqtt_mode: manual` never auto-creates a target.
     - `mqtt_mode: off` disables all MQTT targets at runtime without deleting them from config.
   - **Supervisor answers 400/404** (no MQTT service): log once, mark the target unhealthy with reason `supervisor mqtt service unavailable`, retry with backoff, and never crash the supervisor.
   - **Tests:**
     - resolution via the fake Supervisor
     - reconnect re-fetch picking up rotated credentials
     - no-service path
     - redaction in logs, audit rows, `GET` config API responses and discovery payloads
     - first-boot creation happens exactly once, and a second boot is a no-op
   - **Permissions:** record in `docs/decisions/0009-addon-mode.md` which manifest permission the fetch needs. `services: [mqtt:want]` is expected to be sufficient without `hassio_api`; cite the Supervisor developer docs section. Mark it `PENDING-HIL` and add a HIL checklist step to confirm it on a real box.
3. **Absolute `recording_url` (carry-over M10/M11).** Alert payloads carry a relative `/api/recordings/{id}` today (`alerts/dispatcher.py`).
   - **Setting:** add `public_base_url: str | None`.
     - Validate: `http` or `https` only, no userinfo, query or fragment, and normalize the trailing slash.
     - It can be set via env `TONEWATCH_PUBLIC_BASE_URL`, the add-on option, or `config.yaml` settings if such a section exists. Pick one precedence order, document it and test it.
   - **Payloads:** when set, every alert payload (webhook, MQTT call topic, HA discovery event attributes, script `{recording_url}` placeholder if present) carries `{public_base_url}/api/recordings/{id}`. When unset, keep today's relative URL **and** add `recording_path_relative: true`, so consumers can tell. Update the webhook JSON schema or docs, and the API client if payload schemas are exported.
   - **ADR 0009:** explain that an HA ingress URL is **not** usable as `public_base_url`, because it needs an HA session. Add-on users set the add-on's direct host:port (if they expose it) or rely on the M11 integration's authenticated proxy.
   - **Tests:** every payload type, with and without the setting, plus validation errors.
4. **Hot-backup safety: `tonewatch db checkpoint`.**
   - **Command:** a CLI subcommand that runs `PRAGMA wal_checkpoint(TRUNCATE)` against the live SQLite DB and exits 0.
   - **Busy database:** it must be safe while the server is running. Test it with the app lifespan running and a concurrent write. If the checkpoint is blocked, it retries within a bounded timeout, then exits non-zero with a clear message; it never deletes or rewrites the DB file.
   - **Purpose:** M10b will set the add-on manifest to hot backup with `backup_pre: tonewatch db checkpoint`. A `backup: cold` add-on would stop a paging monitor on every nightly backup.
   - **ADR 0009:** document this.
5. **Sound card input inside the add-on (spike + decision).**
   - **The problem:** the add-on's `audio: true` gives access to HA's PulseAudio (the `PULSE_SERVER` env var and a mapped socket). The image's Debian `libportaudio2` has ALSA and JACK host APIs and **no** PulseAudio host API, so PortAudio sees no Pulse devices unless ALSA is routed to Pulse via the `pulse` ALSA plugin (`libasound2-plugins`) plus an ALSA default PCM config applied only in add-on mode.
   - **Decide in ADR 0009:**
     - (a) add the plugin + an add-on-only `asound.conf` (generated at startup under a writable path such as `/tmp` via `ALSA_CONFIG_PATH`; the root fs is read-only), or
     - (b) don't support Pulse and document `/dev/snd` device mapping instead (the manifest's `devices:` / `audio:`).
   - **If you choose (a):**
     - The image's size margin is only **~2.8 MB** under the 350 MB CI budget. Apply the carry-over lever in the **builder stage only**: `strip --strip-unneeded` on site-packages `.so` files (`av.libs`, `numpy.libs`, others), guarded by the existing in-image import smoke.
     - Report the size from the CI `size` job. **Never raise the 350 MB budget.**
     - Add a smoke assertion that `aplay -L` (or a Python PortAudio query) lists the `pulse` PCM when `PULSE_SERVER` is set, without needing a real server; if that's not possible, mark it `PENDING-HIL`.
   - **Real audio capture** is `PENDING-HIL` either way. Add the checklist step.
6. **Docs.** `docker/README.md` gets an "Home Assistant add-on mode" section covering options, MQTT, `public_base_url`, backup and audio, with a link to ADR 0009. The HIL checklist add-on section gains: MQTT credentials via Supervisor, discovery → integration auto-discover, recordings in Media → tonewatch, hot backup with checkpoint, and audio capture per the ADR decision.
