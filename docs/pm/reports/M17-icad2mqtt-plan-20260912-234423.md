## 3. Parsing strategy

Use `golang.org/x/net/html` and decode the response as ISO-8859-1 before parsing.

1. Walk all tables and rows.
2. Normalize cell text by entity-decoding, converting non-breaking spaces, collapsing Unicode whitespace, and trimming.
3. Identify the header row by required labels rather than table index.
4. Map columns relative to the labeled cells:
   - agency;
   - date/time;
   - type from the blank column between date/time and address;
   - address;
   - municipality from the blank column between address and cross streets;
   - cross streets.
5. Require the expected six-cell row shape.
6. Treat a missing header, malformed row, invalid timestamp, or impossible structure as a page-level parse failure.
7. Keep the last good snapshot and publish no structured data for a failed page.
8. Emit one counter-style log line per failed fetch, without incident fields.

Suggested metrics:

- `icad2mqtt_fetch_total{result}`
- `icad2mqtt_parse_failures_total{reason}`
- `icad2mqtt_incidents{category,status}`
- `icad2mqtt_last_success_timestamp_seconds`
- `icad2mqtt_publish_total{topic,result}`

The health topic should expose `healthy`, `last_success_at`, `last_error_at`, `parse_failures`, and source metadata.

## 4. Data cleaning and normalization

| Field | Raw form | Clean form and rules |
|---|---|---|
| Agency | Visible agency text or category tab label | Trim, collapse whitespace, Unicode case-fold for matching, preserve display form, and map to canonical names only when the tab mapping is reliable. Otherwise retain the source name and category `unknown`. |
| Category | Tab label such as a fire, EMS, or police category | Canonical enum: `fire`, `ems`, `police`, `unknown`; mapping is source-derived and must be tested against tab metadata. |
| Incident type | One cell, possibly containing a code and description | Trim and collapse whitespace; preserve `type_raw`; derive `type_code` only when a stable delimiter/pattern is demonstrated; create `type_key` from case-folded punctuation-normalized text. Code splitting is heuristic. Failure mode: retain the complete value as the description and leave code empty. |
| Address | One combined cell | Preserve `address_raw`; create conservative `address_clean` by whitespace cleanup and case normalization. Split street from trailing business/place text only when a documented, tested pattern is reliable. Otherwise do not split. |
| Municipality | Source code | Preserve `municipality_raw`; map to a name only from an authoritative county/municipal source cited in implementation documentation. Until verified, set `municipality_name` to `unknown`. |
| Cross streets | Delimited text | Preserve `cross_streets_raw`; split only on demonstrated delimiters, trim each value, remove empty entries, and preserve order. |
| Received time | `MM/DD/YY HH:MM`, local Eastern time | Parse in `America/New_York`, emit RFC 3339 with numeric offset, and retain `received_at_raw`. |
| Page updated time | Human-readable `Updated:` row | Parse in `America/New_York`; emit RFC 3339 with offset; reject rather than guess if parsing is ambiguous outside documented rules. |
| ID | Derived from normalized fields | First 16 lowercase hex characters of SHA-256 over `agency|received_at|address|municipality`. |
| Status | Presence on active page | `active` while present; `closed` when absent from a later valid snapshot. |
| Dedupe | Repeated rows or repeated polls | Deduplicate by stable ID, retaining deterministic field precedence and sorting. |

DST rule: use `America/New_York` with embedded `time/tzdata`. For nonexistent spring-forward local times, reject the timestamp and fail the page because silently shifting changes incident identity. For ambiguous fall-back times, select the earlier occurrence consistently and document that limitation. Fixtures must test both transitions.

Heuristics must be marked in code and documentation. Their failure mode is conservative retention of raw text plus an empty/unknown derived field.

## 5. Output contract, schema v1

Base topic: `MQTT_BASE_TOPIC`, default `911/cad`.

- `<base>/incidents`: QoS 1, retained, published only when the incident set changes.
- `<base>/incident`: QoS 1, not retained, one `new`, `updated`, or `closed` event.
- `<base>/availability`: retained `online`/`offline`, with MQTT LWT.
- `<base>/health`: retained health/status JSON.
- Existing `MQTT_TOPIC` raw HTML topic remains supported and is controlled by `PUBLISH_RAW`, default `true`.
- Optional HA discovery is recommended for retained per-category active-incident counts; individual address-bearing incidents should not be exposed as retained HA entities.

## 6. Polling etiquette and resilience

- Enforce a minimum interval of 60 seconds; allow larger configured intervals.
- Send `If-None-Match` and `If-Modified-Since` when available.
- Treat `304 Not Modified` as a successful unchanged fetch.
- Use a 15-second request timeout and a response cap of 5 MiB.
- On errors, back off exponentially with full jitter, capped at a reasonable maximum, while respecting the configured minimum interval.
- Do not publish partial or malformed results.
- Use the configured `icad2mqtt/1.0` User-Agent.
- Check `robots.txt` and terms of use before production polling; obey explicit disallow or rate requirements and document any ambiguity for the user.
- Never log incident contents, addresses, raw HTML, or payload bodies.
